# On Lisp を Clojure で写経する

Paul Graham『On Lisp』の内容を、Common Lisp原文からClojureへ移植しながら読み進めるプロジェクトです。2章から24章（最終章）まで、一通り通しています。


## 構成

| 章 | 内容 | 形式 |
|---|---|---|
| 2〜10章 | 関数型プログラミング、クロージャ、マクロの基礎 | 読書メモ（`.txt`） |
| 18・19章 | 破壊的マクロ最適化／クエリコンパイラ（Prologの前段） | Leiningenプロジェクト |
| **20章** | **継続**（`=defn`/`=bind`/`=values`によるCPS変換） | Leiningenプロジェクト |
| **21章** | **マルチプロセス**（`fork`/`wait`/`yield`による協調的マルチタスク） | Leiningenプロジェクト |
| **22章** | **非決定性**（`choose`/`fail`によるバックトラッキング探索、`mark`/`cut`） | Leiningenプロジェクト |
| **23章** | **ATNを使ったパージング**（拡張状態遷移ネットワークによる構文解析） | Leiningenプロジェクト |
| **24章** | **Prolog**（Common Lispへのミニ論理プログラミング処理系の実装） | Leiningenプロジェクト |

18章以降は各章ごとに独立したLeiningenプロジェクト（`project.clj`）として構成されており、`lein repl`でその章のコードを直接動かして確認できます。`trial-and-error/`ディレクトリには、実装に至るまでの試行錯誤の記録を残しています。


## 20〜24章について

Common LispにはSchemeの`call/cc`のような第一級継続がありません。20章は、動的変数`*cont*`と`=defn`/`=bind`マクロを使ってCPS（継続渡しスタイル）変換を手作りし、「次に何をするか」を明示的な値として扱えるようにするところから始まります。

この20章で作った土台1つが、21〜22章で形を変えて再利用されているのが、このプロジェクトの読みどころです。

- **21章（マルチプロセス）**: プロセスの中断・再開を、「条件が満たされたら実行する継続」を保存・呼び出しすることで実装。20章の`=defn`/`=bind`を使った版（`cps.clj`）と、使わない素朴な版（`fnc.clj`）の両方を実装し、挙動を比較できるようにしてある。
- **22章（非決定性）**: `choose`/`choose-bind`が「他の選択肢を試すための継続」をスタック（`PATHS`）に積んでいき、`fail`がそこから1つ取り出して呼ぶことでバックトラッキング探索を実現。原著の`mark`/`cut`（探索の枝刈り）に加えて、`true-choose`（同じ選択肢への無限再帰を検出する版）も追加で実装している。
- **23章（ATN）**: 文法をノードのネットワークとして表現し、名詞句・前置詞句などの副ネットワークを合成して英文を解析する。バージョンを`atn1`から`atn9`まで段階的に発展させながら実装。
- **24章（Prolog）**: 19章のグランドファクトのみのクエリエンジンに、変数を含む単一化・バックトラッキング・再帰的なルールを加えて、簡易的なProlog処理系をLisp上に構築する（`compiler.clj`/`compiler2.clj`/`interpreter.clj`の複数バージョンあり）。


## 原著の写経を超えた応用実験

20章・22章で作った土台を使って、原著には出てこない題材を独自に実装してみた実験も含まれています。

- **[`signup.clj`](OnLisp_chap20/onlisp/src/onlisp/chap20/signup.clj)**（20章）: 継続を使った多ページのサインアップフォームのシミュレーション。`get-input`が現在の`*cont*`（＝このページの入力を受け取ったら次にすること）を保存していったんREPLへ制御を返し、`submit!`が次のリクエストが来たという想定でその継続を呼んで再開する。パスワードと確認用パスワードが不一致の場合は、メールアドレス入力後の状態（`ask-password`）まで戻ってやり直す仕組みも実装している。
- **[`username.clj`](OnLisp_chap22/onlisp/src/onlisp/chap22/username.clj)**（22章）: `choose-bind`で`taro`, `taro1`, `taro2`, ...と候補を1つずつ試し、登録済みならバックトラックして次の候補へ、空いていたら`cut`で残りの未試行候補を刈り込む、というユーザー名の自動提案。`mark`/`cut`が実際に効いているかを、探索終了後に`fail`を呼んで即座に`[end]`になることで検証している。


## 他のClojure写経プロジェクトとの比較

2026年8月時点でGitHub上の関連プロジェクトを調べた限り、20章（継続）以降まで到達している公開Clojureプロジェクトは見つかりませんでした。最もスターの多い[rickhall2000/OnLisp](https://github.com/rickhall2000/OnLisp)は11章まで、最も進んでいる[pangloss/onlisp-in-clojure](https://github.com/pangloss/onlisp-in-clojure)でも19章までで止まっています。

余談として、「なぜ他に完走している例が少ないのか」をClaudeと雑談してみたところ、大きく2つの理由が考えられる、という話になりました。

1. 難度そのものに加え、CLからClojureへの意味論の差（動的スコープの挙動の違い、非衛生的マクロの前提の違いなど）を自分で埋める作業が上乗せされること
2. 「On Lispを読んでいる」かつ「Clojureにも関心があり自分で移植したい」という、二重に絞られた読者層でしか成立しない企画であること

内容そのものが古びて魅力を失った、という説には懐疑的でした（CPS変換やマクロによるパラダイム埋め込みは今でも通用する話題のため）。あくまで雑談ベースの仮説であり、検証したわけではありません（詳しいやり取りは[調査メモ](OnLisp_他のClojure写経プロジェクト調査.txt)を参照）。


## 動かし方

各章のディレクトリ（例: `OnLisp_chap22/onlisp/`）に移動し、

```sh
lein repl
```

`:repl-options {:init-ns onlisp.core}`によりREPL起動時に`onlisp.core`が読み込まれるので、`core.clj`内でrequireされている各章の名前空間の関数をそのまま呼び出せます。
